`main` can be protected by a ruleset, because the release no longer pushes to it as `github-actions[bot]`.

`SECURITY.md` listed *Branch Protection* as a Scorecard check this project could not pass, next to *Code-Review*. Only one of those was true. Code-Review counts reviews by somebody other than the author and there is one maintainer, so it is low by construction. Branch Protection was not that kind of limit: it was blocked by a mechanism, and the mechanism turned out to be fixable.

The release workflow pushes the changelog commit and its tag to `main`, and it pushed them with `GITHUB_TOKEN`. **No ruleset can exempt that identity.** Bypass is granted to repository roles, to deploy keys and to *installed* GitHub Apps; `github-actions[bot]` is a first-party integration and is none of the three, so a ruleset naming it is rejected outright — "the ruleset you are importing contains an invalid actor". Any rule strong enough to be worth having would have broken every release, which is why the entry said a protection rule "has to be written to allow that" and none ever was.

The `release` job now mints its token from a GitHub App installed on this repository, and `actions/checkout` keeps it so `git push` uses it. An App is something a bypass list can name. It is scoped to `contents: write` on this repository alone and the token expires with the run — a personal access token would have been one secret instead of two, and a standing credential with far more reach than the one push it exists for.

Two new repository secrets, `RELEASE_APP_ID` and `RELEASE_APP_PRIVATE_KEY`, and a step that checks both are set before anything else runs: without it the job dies inside the token action with `Input required and not supplied: app-id`, which names nothing worth doing. [The setup is written down](https://batuhanzorbeyzengin.github.io/rebasis/development/release/#the-push-to-main-is-made-by-a-github-app), including the step that is easiest to forget — adding the App to the ruleset's bypass list, whose absence surfaces as a failed push at the end of a release rather than at the start.
