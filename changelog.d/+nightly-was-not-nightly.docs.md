Five documents said the golden corpora and the macro benchmarks run nightly. Nothing has ever run them on a schedule.

The workflow that would have — `workflow_dispatch` plus a 02:00 cron — drives the maintainer's GPU host through `scripts/`, and neither the scripts nor the workflow are in a clone, so the file was never committed. A `schedule:` trigger only fires from the default branch; a file that is not on it fires never. GitHub reports no run, and the repository holds none of the secrets its SSH step names.

What is true is weaker, and is now what the pages say: that layer runs when somebody runs it. `docs/stability.md`'s support table, which is the page an evaluator reads first, had a column headed "Nightly, on the project's own host"; it is headed "Run by hand" and says why the correction was needed. `docs/development/testing.md`, `benchmarks/README.md`, `ci.yml`'s header, `docs/m4-findings.md` §7 and two test docstrings said the same thing and no longer do. `CONTRIBUTING.md` asks for the golden tests after a change to adapter or metric behaviour; that request is answered by a person, and calling it a gate was the mistake.

Two further claims were re-measured rather than repeated. **macOS is back in CI** — `ROADMAP.md` and `docs/stability.md` both said Linux was the only operating system, and both said the narrower leg that would clear the `faiss-cpu`/`torch` OpenMP conflict had not been written. It has: `core install` installs no extras, so neither library is present, and it runs `unit or property or contract` on `macos-latest` as well as `ubuntu-latest`. That covers the storage layer, which is where the platforms differ. It does not cover a real store on macOS — with no extras the five live backends skip and only the in-memory one runs, and that limit is now stated where the claim is made. And **the coverage figures were stale**: `storage/atomic.py` is at 93.3%, not 92.5%, and the total is 84.9%, not 81.8%.
